# Julia originales (2025-12-25)

Dos scripts sueltos en Julia, anteriores al repo, traídos tal cual el 2025-12-25:

- `rotacion3d.jl`: venía de Dropbox `Agrimensura/Sistemas de Coordenadas/ejercicios/`. Es un port a Julia de `unidades/_legacy/rotacion3d.py` (rotaciones 3D con la fórmula de Rodrigues: matriz R(θ) alrededor de un eje arbitrario, rotación incremental vs. directa, autovalores 1 y e^{±iθ} con su interpretación geométrica, traza = 1 + 2cosθ, det = 1, R·Rᵀ = I). No se porta de vuelta: ya es el mismo programa. Verificado el 2026-10-17: mismas funciones (`matriz_antisimetrica`, `matriz_rotacion`, `rotar_incremental`, `fmt`, `fmt_complejo`, `imprimir_matriz`, `angulo_entre`, `seccion_incremental`, `seccion_autovalores`, `validar`, `main`), docstrings con el mismo texto (sólo cambian la línea de firma y el formato Markdown de "Parámetros/Devuelve" por convención Julia), y con los argumentos por defecto (`julia rotacion3d.jl` vs. `uv run python ../../unidades/_legacy/rotacion3d.py`) las 73 líneas de salida coinciden salvo formato de vectores (`[0. 0. 1.]` vs. `[0.0, 0.0, 1.0]`), `True`/`true`, el orden del par conjugado ±i (LAPACK lo devuelve en distinto orden) y roundoff de 10⁻¹⁶. Se corre con `julia rotacion3d.jl` (sólo biblioteca estándar).
- `test.jl`: venía de iCloud `Julia/`. Prueba de `LinearAlgebra` con una 3×3 simétrica: resuelve A·x = b, autovalores, descomposición LU, determinante, inversa, norma de Frobenius y número de condición.
- `test.py`: port de `test.jl` con numpy + `scipy.linalg.lu`, misma salida de texto (los vectores y matrices se imprimen con el formato de Julia). Comparado contra `julia test.jl` el 2026-10-17: solución [1.0, 1.0, 1.0], L, U, norma de Frobenius y número de condición idénticos dígito a dígito; autovalores iguales hasta ~10⁻¹⁵ (1.9213469419616898 vs. ...902, etc.); determinante 67.0 en Julia vs. 66.99999999999997 en numpy (distinta rutina LAPACK); inversa igual salvo el último dígito en dos entradas. Correr con `uv run python test.py`.
